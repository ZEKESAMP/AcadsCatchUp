1. PROJECT PURPOSE & CORE OBJECTIVES
--------------------------------------------------------------------------------
AcadsCatchUp is an advanced, dark-themed desktop academic management system
built to solve student academic deficiencies caused by class absences, medical
emergencies, official school representations, and schedule conflicts.

The application serves three key roles:
1. ADMINISTRATOR (F4TAL):
   - Full master authority over all accounts (Admins, Professors, Students).
   - Assigns dedicated curriculum subjects and teaching year levels to faculty.
   - Manages school subjects and inspects faculty/student bug reports.
2. PROFESSOR / INSTRUCTOR:
   - Manages missed activities, quizzes, exams, and assignments for students.
   - Scoped workspace isolating classes and deficiencies to their assigned subjects.
   - Multi-subject teaching support with granular course-level student filtering.
   - Self-service Student Enrollment modal to enroll students directly into subjects.
   - Grades submitted make-up work and generates structured CSV reports.
3. STUDENT:
   - Tracks overdue, pending, submitted, and graded make-up requirements.
   - Submits work directly inside the application with custom notes and timestamps.
   - Receives automatic Windows Toast and in-app alerts when deficiencies are posted
     or submissions are graded.
   - Sends bug reports and support requests directly to the Administrator.

3. SYNTAXES, STYLES & FILE EXTENSIONS
--------------------------------------------------------------------------------
* .java (Java Source Files):

  - Model Layer: Immutable entity definitions (User, Subject, MissedItem, InboxMessage, HelpReport).

* .sql / .db (SQLite Database File):
  - Relational schema with AUTOINCREMENT keys, ON DELETE CASCADE foreign keys,
    and indexed lookups.

* .png / .ico (Visual Assets):
  - High-resolution blue book branding icon for window titlebars, modals, and system tray.


4. DATABASE SCHEMA (acadscatchup.db)
--------------------------------------------------------------------------------
1. users:
   - id (INTEGER PRIMARY KEY AUTOINCREMENT)
   - username (TEXT UNIQUE NOT NULL)
   - password (TEXT NOT NULL)
   - full_name (TEXT NOT NULL)
   - role (TEXT NOT NULL — 'ADMIN', 'PROFESSOR', 'STUDENT')
   - program (TEXT — e.g. 'BSIT', 'BSCS')
   - year_level (INTEGER — 0 for All Years, 1 for 1st Year, 2 for 2nd Year, etc.)

2. subjects:
   - id (INTEGER PRIMARY KEY AUTOINCREMENT)
   - code (TEXT UNIQUE NOT NULL)
   - name (TEXT NOT NULL)

3. enrollments:
   - student_id (INTEGER NOT NULL)
   - subject_id (INTEGER NOT NULL)
   - PRIMARY KEY (student_id, subject_id)
   - FOREIGN KEY (student_id) REFERENCES users(id) ON DELETE CASCADE
   - FOREIGN KEY (subject_id) REFERENCES subjects(id) ON DELETE CASCADE

4. professor_subjects:
   - professor_id (INTEGER NOT NULL)
   - subject_id (INTEGER NOT NULL)
   - PRIMARY KEY (professor_id, subject_id)
   - FOREIGN KEY (professor_id) REFERENCES users(id) ON DELETE CASCADE
   - FOREIGN KEY (subject_id) REFERENCES subjects(id) ON DELETE CASCADE

5. missed_items:
   - id (INTEGER PRIMARY KEY AUTOINCREMENT)
   - student_id (INTEGER NOT NULL, FK users)
   - subject_id (INTEGER NOT NULL, FK subjects)
   - item_type (TEXT NOT NULL — 'ACTIVITY', 'QUIZ', 'EXAM', 'ASSIGNMENT')
   - item_name (TEXT NOT NULL)
   - date_missed (TEXT NOT NULL)
   - deadline (TEXT NOT NULL)
   - status (TEXT NOT NULL — 'PENDING', 'SUBMITTED', 'GRADED')
   - notes (TEXT)
   - created_by (INTEGER NOT NULL, FK users)

6. inbox_messages:
   - id (INTEGER PRIMARY KEY AUTOINCREMENT)
   - sender_id (INTEGER), sender_name (TEXT), sender_role (TEXT)
   - recipient_id (INTEGER NOT NULL, FK users), recipient_name (TEXT)
   - title (TEXT NOT NULL), message (TEXT NOT NULL)
   - item_id (INTEGER), item_name (TEXT), subject_code (TEXT)
   - msg_type (TEXT — 'NOTICE', 'SUBMISSION', 'GRADED', 'MISSED_ITEM', etc.)
   - is_read (INTEGER DEFAULT 0)
   - created_at (DATETIME DEFAULT CURRENT_TIMESTAMP)

7. help_reports:
   - id (INTEGER PRIMARY KEY AUTOINCREMENT)
   - user_id (INTEGER NOT NULL, FK users), user_name (TEXT), user_role (TEXT)
   - category (TEXT NOT NULL), subject (TEXT NOT NULL), description (TEXT NOT NULL)
   - status (TEXT DEFAULT 'OPEN'), admin_reply (TEXT)
   - created_at (DATETIME DEFAULT CURRENT_TIMESTAMP)

6. CORE FEATURES & ARCHITECTURAL HIGHLIGHTS
--------------------------------------------------------------------------------
* Multi-Subject Faculty Handling:
  - Admin can assign one, two, or multiple subjects to any professor using a
    scrollable checklist in Manage Users.
  - The Manage Users directory table dynamically aggregates assigned subjects
    using SQLite GROUP_CONCAT (e.g. "CP, DSA").

* Granular Multi-Course Professor Scoping:
  - Scope Selector dropdown offers:
    * "All My Subjects (CP, DSA)" (default across all taught classes)
    * "Only CP Students (Computer Programming)" (isolated course roster)
    * "Only DSA Students (Data Structure)" (isolated course roster)
    * "All Enrolled Students" (school-wide directory option)
  - Subject filter dropdown lists only the professor's assigned subjects.
  - Missed items belonging to other faculty are strictly hidden.

* Faculty Teaching Year Level Assignment & Filtering:
  - Admin can assign specific teaching years (e.g. "1st Year") or "All Years".
  - Displayed in user directory table under the "Year" column.
  - Professor dashboard features a "Year Level" filter that auto-defaults to the
    professor's assigned teaching year.

* Student Subject Self-Enrollment Modal (🎓 Enroll):
  - Professors can click "🎓 Enroll" directly from the dashboard sidebar.
  - Opens a dark FAQ-styled modal to search students, filter by year, select
    candidates via checkboxes, and batch enroll them into their subject.

* Strict Role Privilege Hiding & Account Scoping:
  - Non-admin professors and students cannot view or access:
    * "👥 Manage Users"
    * "＋ Add Student"
    * "📚 Add Subject"
    * "📥 Bug Reports Inbox"
  - Master Administrator (F4TAL) is strictly isolated and hidden from student/professor lists:
    * Completely excluded from the "Choose Dedicated Professor" submission dropdown.
    * Only verified professors (`role = 'PROFESSOR'`) teaching the deficiency course appear as options.
    * Master Administrator cannot be accidentally targeted for deficiency submissions.

* Custom FAQ-Styled Modal Dialogs (CustomAlert.java):
  - Custom undecorated modals with #0f1117 dark background, #2d3255 border,
    blue book branding icon, draggable header bar, and "✕" close button.
  - Attached via initOwner() to prevent child dialogs from detaching or hiding
    when the parent window is minimized or restored.
  - Keyboard shortcuts: ESC to close, ENTER to confirm.

* Live Notification & Windows Toast Integration:
  - 8-second background daemon poller checks for new student deficiencies and grades.
  - Automatically raises native Windows desktop balloon/toast notifications and
    in-app banners with audio feedback.
  - Categorized notices: "Missed Activity", "Missed Quiz", "Missed Exam", "Missed Assignment".

* Discord-Style Windows System Tray Integration:
  - Minimizes seamlessly to the Windows notification tray (close-to-tray behavior).
  - Single-instance process management (prevents duplicate instances in Task Manager).
  - Right-click tray menu:
    * "Show AcadsCatchUp"
    * "Exit AcadsCatchUp" (terminates all background daemons cleanly).

* Comprehensive CSV Reporting:
  - Instant one-click export of deficiency records and student rosters for faculty.
